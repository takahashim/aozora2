# 外字注記辞書

青空文庫・外字注記辞書を機械可読にしたもの。`tools/extract_gaiji_chuki.rb` で
再生成できる。

外字注記そのものの記法と変換規則は [docs/spec-encoding.md](../../../docs/spec-encoding.md)
5 章。本書はその**外部データ**についての説明で、記法の仕様ではない。

- 出典: <https://www.aozora.gr.jp/gaiji_chuki/gaiji_chuki.pdf>
- 版: 青空文庫外字注記辞書編集グループ・**改訂第八版訂正版（2011-08-06）**
- 利用条件: 青空文庫本体と同じ

```
curl -O https://www.unicode.org/ivd/data/2022-09-13/IVD_Sequences.txt
curl -O https://raw.githubusercontent.com/cjkvi/cjkvi-ids/master/ids.txt
ruby tools/extract_gaiji_chuki.rb gaiji_chuki.pdf IVD_Sequences.txt ids.txt \
    crates/aozora-core/data
```

poppler-utils（pdftotext・pdftocairo）が要る。PDF 自体の読み取りは `tools/mini_pdf.rb`
（標準ライブラリのみ。この PDF は古典的な xref 表・FlateDecode のみ・オブジェクト
ストリーム無しなので、汎用の PDF ライブラリを持ち込まずに済む）。

`id` は `p<ページ>-<ページ内連番>` で、上の版のページ付けに依存する。版を上げるときは
2 つの TSV を同時に作り直すこと。

## `gaiji_chuki.tsv` — 9203 エントリ

| 列 | 内容 |
|---|---|
| `id` | エントリの識別子 |
| `page` | PDF のページ番号（字形を目で確かめたいときの参照先） |
| `radical` / `strokes` | 部首（202 種）と画数 |
| `desc` | 注記の説明（`※［＃「口＋畢」…］` の `口＋畢`） |
| `jis` / `level` | 面区点と水準（4040 件） |
| `unicode` | U+ の値（4037 件） |
| `sub` / `sub_kind` / `sub_rule` | 代用してよい字・種別・規準番号（1133 件） |
| `cross` | 別部首への再掲（★）なら 1 |
| `ivs` | 字形の Adobe-Japan1 異体字セレクタ列（823 件。例 `51E1 E0101`） |
| `cid` | 字形の CID（`ivs` が引けなかったときの手がかり） |
| `glyph` | `1` なら `gaiji_chuki_glyphs.tsv` に輪郭がある |
| `ids` | 説明を組み立ての IDS にしたもの（7821 件。例 `⿰旬力`） |
| `ids_char` | `ids` を CHISE の IDS 表で引いた字（5699 件） |
| `glyphwiki` | `ids` から作った GlyphWiki の合成グリフ名（例 `u2ff0-u65ec-u529b`） |

`ids` が 1 文字のときは組み立てではなく「その字の別字形」の意味なので、`ids_char` と
`glyphwiki` は空にしてある。

`desc` が**両方向の結合キー**になる。読む側は「説明だけの注記」を字へ解決でき、書く側
（OCR など）は字から慣用の注記を引ける。

`sub_kind` の内訳は包摂適用 984・デザイン差 96・78互換包摂 29・統合適用 24。代用字は
1 文字とは限らず、37 件は代用字自体が外字注記になっている（`→［包摂適用 ※［＃「（冫＋
臣＋犯のつくり）／れんが」、第3水準1-87-58］］`）。

## 符号位置を持たない 1127 件をどう同定するか

面区点や U+ があれば字形は符号位置で決まる。問題はコードを持たない 1127 件——包摂適用・
デザイン差・統合適用、つまり「符号位置が同じで字形だけ違う」例示字形そのもの——で、
ここは PDF の字形が唯一の情報源になる。

**字形の輪郭ではなく、content stream の CID を読む。** 字形欄は非埋め込みの Ryumin-Light
で描かれているものが多く、描画系は代替フォントで CID を解決できずに .notdef（□に×）を
出す。輪郭を取っても豆腐にしかならない（この方式で 1045 件取ったうち 644 件が豆腐だった）。
一方 PDF には「どの CID を描くか」が書かれていて、Ryumin-Light は Adobe-Japan1 なので
Unicode の IVD（Adobe-Japan1 コレクション）で異体字セレクタ列に落ちる。

```
p10-4 「凡」→［包摂適用 凡］規準37
    content stream:  1 0 0 rg /F8 Tf [<36d9>]TJ   ← 赤・Ryumin-Light・CID 14041
    IVD:             CID+14041 → U+51E1 U+E0101
```

| 同定できた手段 | 件数 |
|---|---|
| **IVS（Adobe-Japan1・CID から直接）** | **823** |
| MJ 文字図形（輪郭照合。`gaiji_chuki_mj.tsv`） | 137 |
| IDS から字（説明の組み立てから） | 284 |
| GlyphWiki の合成グリフ名 | 444 |
| **いずれかで同定** | **1006（89%）** |
| どれも無い | 121 |

埋め込みサブセットフォントの CID はそのフォント内でしか意味を持たず ToUnicode も無いので、
そちらは輪郭を残すしかない（222 件）。

## 説明文から組み立てを導く（`ids` 列）

説明文は部品の組み立てを表す小さな言語になっている。

| 記法 | IDS | 例 |
|---|---|---|
| `＋` | ⿰（左右） | `口＋畢` → ⿰口畢 |
| `／` | ⿱（上下） | `髟／舌` → ⿱髟舌 |
| `＜` | ⿴/⿵/⿷/⿶ | `囗＜力` → ⿴囗力、`匚＜工` → ⿷匚工（囲む側で変わる） |
| `−` | 対応なし | `尓−小`（変換できない） |

部品は文字そのもののほか「にんべん」のような呼び名や「膠のつくり」のような他の字からの
参照で書かれる。前者は `tools/gaiji_ids.rb` の語彙表、後者は CHISE の IDS 表の分解で解く。

**規則の妥当性はデータ自身で検算できる。** 符号位置を持つエントリで「説明 → IDS →
IDS 表 → 符号位置」がエントリ自身の U+ と一致するかを見ると、2769 件中 2728 件が一致した
（**98.5%**）。不一致 41 件は `にんべん＋蜈のつくり → 俣 / 俁` のような字形の揺れで、
辞書と CHISE のどちらが正しいか判断が要る性質のもの。

符号位置が無い組み立ては GlyphWiki の合成グリフ名で参照できる。`旬＋力`（『小公女』が
底本の字形を示すために使っている字）は <https://glyphwiki.org/wiki/u2ff0-u65ec-u529b>
に実在する。部品が増えるほど登録は少なくなる。

## `gaiji_chuki_mj.tsv` — 輪郭照合で特定した 137 件

`tools/match_glyphs_ipamj.rb` で作る**任意の**成果物。IPAmj明朝がライセンス同意の先に
あり、MJ 文字情報一覧表も別途入手が要るので、抽出器本体とは分けてある。対象は `glyph=1`
の 222 件で、代用字の異体字を IPAmj明朝から描いて重なりの良いものを選ぶ。

較正では、正解と分かっているペアの IoU が中央値 0.61、無関係なペアが 0.22 で分離する。
`iou>=0.40` かつ 2 位と 0.05 以上の差があるものだけを載せた（137 件・IoU 中央値 0.95）。
`runner_up` と `candidates` を残してあるので、確度は利用側でも判断できる。

IoU は塗り方の実装に敏感で、走査線の丸めが違えば 0.02 ほど動く。**どの MJ 図形を選ぶかは
変わらない**（先に Python で書いた版と共通 135 件すべてで一致した）が、閾値ぎりぎりの
ものは出たり出なかったりする。件数を当てにせず `iou` と `runner_up` を見ること。

## `gaiji_chuki_glyphs.tsv` — 222 字

| 列 | 内容 |
|---|---|
| `id` | `gaiji_chuki.tsv` と同じ |
| `part` | パーツ番号（0 から） |
| `fill` | 色（下表） |
| `dx` | 先頭パーツからの水平位置 |
| `d` | SVG のパスデータ |

1 文字が複数パーツで組まれることがある。単一のフォントに字が無く部品を並べているためで、
同じ `id` の行を `dx` だけ右にずらして重ねると 1 文字になる。

色は辞書の凡例がそのまま残る。

| `fill` | 意味 | 件数 |
|---|---|---|
| `rgb(0%, 100%, 0%)` | JIS X 0213:2004 で例示字形変更 | 164 |
| `rgb(100%, 0%, 0%)` | 包摂される字（底本の字形） | 42 |
| `rgb(50%, 50%, 50%)` | 参考掲載 | 16 |

## 取り込むときに引っかかったこと

- **表示字形は文字として取らない。** 外字は ToUnicode を持たない埋め込みサブセット
  フォント（GT2000・花園明朝など）で描かれ、pdftotext は BMP 外の字を別の字に取り違える
  （U+ を持つ 4021 件中 186 件が食い違い、うち 141 件が BMP 外）。正は注記本文であり、
  そちらはかなと常用漢字と ASCII だけなので確実に取れる。
- **制御文字。** 同じ理由で、字形は U+001E などの制御文字として出てくる。XML として
  不正なので落とす（位置しか使わない）。
- **描画系の豆腐を字形と取り違えない。** 非埋め込みフォントの字は .notdef になるので、
  輪郭を取ると □に× が入る。CID を読む方式に変えた理由がこれ。
- **`ページ数-行数` はプレースホルダ**（「ここに底本のページ-行を書く」という指示）
  なので取り除いてある。

## 使い道

変換経路には入れない。参照実装 aozora2html はこの辞書を持たないので、いま `※` で
出ている字を解決し始めると出力が変わり、オラクル（byte 一致）が悪化する。想定して
いるのは次の 2 つ。

- **診断** — 辞書に無い綴りの検出（入力ミス）、代用字の提案。`analysis` の診断は
  docs/plan-lsp.md
- **生成側の支援** — 字から慣用の注記を引く逆引き（スキャン画像からの生成など）

コーパス全 17509 作品で、面区点を持たない注記は 7029 箇所 / 2735 種あり、`desc` で
引けるのは 3395 箇所 / 820 種（うち 770 種は字が一意に決まる）。引けないものは説明の
書き方の揺れが多く、正規化でさらに拾える余地がある。
