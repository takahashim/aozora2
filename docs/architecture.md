# aozora2 アーキテクチャ設計メモ

改訂: 2026-07

青空文庫記法テキストを HTML（将来的には EPUB・プレーンテキスト等）へ変換するツール
aozora2 の設計方針をまとめる。

## 0. この文書自身の位置づけ（最初に読むこと）

**この文書は規範ではない。** 規範は、仕様（実行可能な実例つき）・適合性スイート・
型システムが強制する構造、の側にある。この文書と実態が食い違ったら、
**検証可能な側（テストが通る実態）が正しく、この文書が古い**。
この文書の役割は「真実がどこに置かれているか」の案内図に徹することである。

- 目標: 青空文庫の記法とデータを 100 年以上保守する。担い手は何度も入れ替わり、
  10〜20 年後には現在の設計文書が失われている・読まれていない前提で、
  **知らない誰かが新しく正しいプロセッサを書け、記法とコーパスを拡張し続けられる**
  体制の基盤をつくる。
- 前提の機能要件: 参照実装 [aozora2html](https://github.com/aozorahack/aozora2html)
  と機能的に等価（互換モードでは byte 一致）であること。
- 工数・ツール自体の後方互換性は評価軸に含めない。最終成果物の良さのみを基準とする。

## 1. 脅威モデルと荷重原則

100 年スパンで実際に起きる劣化は「喪失」よりも「腐敗とドリフト」である。

| アーティファクト | 生存性 | 劣化モード |
|---|---|---|
| コード | 残る | **ドリフト**: 担い手交代のたび、当初設計から外れた実装が混入する |
| コメント | 残る | **腐敗**: 現在形で主張し続けるが、嘘になっても何も壊れない |
| 設計文書 | 残るかもしれない | 腐敗・散逸・不読 |
| テスト・データ | 残る | 壊れれば CI が赤くなる（＝腐敗が検出される） |

ここから設計の最上位原則を置く。

> **荷重原則: 真実は「偽になったとき何かが壊れる場所」にだけ置く。**

置き場所の信頼度（強い順）:

| 置き場所 | 偽になったとき | 使い道 |
|---|---|---|
| 型・crate 依存グラフ | コンパイルが落ちる | アーキテクチャ（層の壁・不正状態の排除） |
| 適合性スイート／仕様内の実行可能実例 | CI が赤くなる | 挙動の規範 |
| 機械可読な記法定義データ（実装が**実際に消費**するもの） | パースが壊れる | 言語の定義 |
| コミットメッセージ・日付つき決定記録 | 腐らない（過去形の事実） | 「なぜ」の記録 |
| 設計文書（現在形の prose） | 何も壊れない | 薄い案内図のみ。詳細を持たない |
| コード内コメント | 何も壊れない | **規範を書かない**（下記コメント方針） |

**コメント方針**: コメントは規範を運ばない。規則・挙動の根拠はすべて仕様 ID ＋
適合ケースに置き、コメントは最大でも `SPEC:notation/jisage-oneline 参照` のような
**ポインタ**に留める。ID への参照は腐らない（規則が変わればテストが赤くなり、
grep で実装箇所がすべて見つかる）。
現状のコードには参照実装の挙動を説明する長文コメントが多数あるが
（2025-26 の互換性改修で追加されたものを含む）、これらは仕様へ移して
ID 参照へ薄める**移行対象**である。

**記法定義データへの注意**: 定義テーブルは、パーサが実際に消費する入力で
なければならない。コードの脇に置かれるだけの「参照用テーブル」は構造化された
コメントに過ぎず、同じ速度で腐る。荷重していることがデータ駆動化の本質的要件。

## 2. 一次アーティファクトと権威

一次アーティファクト（生存必須・自己記述・可能な限り言語中立）は次の 5 つ。

1. **仕様書**（`docs/spec/`・整備中）——CommonMark / test262 型。規範 prose に
   **実行可能な実例**を埋め込み、実例がそのまま適合性テストになる。
   処理モデル（行指向・前方参照・暗黙クローズ）、エンコーディング層
   （CP932、CRLF のみが改行、外字画像体系）、互換プロファイル（Quirks 全列挙）を含む。
2. **記法定義データ**——安定 ID つきの機械可読な規則索引（言語中立ファイル）。
   青空文庫「注記一覧」に対応。パーサはこれを消費する薄い機構となる（荷重原則）。
3. **適合性スイート**——最小ケースのデータ集。compat プロファイル（quirks on＝
   参照実装 byte 一致）と clean プロファイル（quirks off）の二本立て。
   各ケースは規則 ID に紐付く。
4. **アーカイブされたオラクル**——参照実装 aozora2html の全 17,397 件の出力
   （aozora-htmlcheck リポジトリの `oracle/`）。参照実装が実行不能になっても
   互換性の定義がデータとして残る。来歴（生成方法・日付・参照実装のリビジョン）を
   付して保存する。
5. **コード（aozora2）**——**挙動の一次アーティファクト**（実行可能で、適合スイート
   により自己検証される）。ただし**意図・設計の担体としては信頼しない**（ドリフト
   するため）。意図は型構造と仕様データが持つ。

### 権威の反転（マイルストーン）

- 現在: 参照実装のオラクルが正しさを定義し、仕様は導出物。
- 目標状態: **仕様＋適合性スイートが規範**になり、参照実装は「凍結された歴史的
  証拠」に降格する。互換性は Ruby を動かさなくても保存される
  （アーカイブ済みオラクル＋ Quirks 列挙＋適合ケース）。

### 三つの真実源と優先順位

真実源は三つあり、互いに矛盾する。矛盾時の解決ポリシー:

| 真実源 | 位置づけ | 矛盾したら |
|---|---|---|
| 注記一覧（青空文庫の公式ドキュメント） | 意図 | 意味論の第一参照。ただし挙動の最終判定には使わない |
| 参照実装 aozora2html | 事実上の挙動 | **互換モードの挙動はこれが勝つ**。ただしバグ・実装都合は Quirks として隔離しラベル付けする |
| 公開コーパス（cards/ の HTML） | 現実 | 権威としない（約 6 割は古い世代の生成器の出力のまま） |

## 3. コードのアーキテクチャ（一つの適合実装として）

```
ソース
  → [記法定義データ] を解釈するパーサ
  → RawAST（位置つきが望ましい。忠実・前方参照未解決・ブロックは平坦マーカー）
  → Lowerer（前方参照解決・ブロック部分木化・行束ね・break 計算）
  → 中立AST（block / line / inline の木）
  → 各バックエンド（HTML / EPUB / plain text …）
  ＋ Quirks（参照実装の癖を隔離・明示ラベル）
```

### 3.1 中立AST（block / line / inline）

青空文庫記法の論理構造は **ブロック ⊃ 行 ⊃ インライン** の 3 層
（Markdown/HTML の block/inline 分割と同型）。

```rust
// 概念図
enum Block {
    Line { inline: Vec<Inline>, brk: Break },          // 内容の1行
    Nested { kind: BlockKind, children: Vec<Block> },  // 字下げ/地付き/見出し/ぶら下げ…
}
enum Inline { Text, Ruby { base, ruby }, Style, Gaiji, Accent, Img, Tcy, /* … */ Note }
```

- **行は第一級の構造ノード**。行スコープのコマンド（`［＃地付き］`・一行
  `［＃N字下げ］`）が存在し、ソース 1 行 ≒ 作品の論理行であるため、
  行はレンダリングの都合ではなく構造である。
- **ブロックは部分木**。「ブロックだけの行」は器（Nested）に吸収され、
  `<br/>` 特別扱いの多くが構造から自然に従う。
- **インライン葉は raw/ast で共有**。構造層だけが本当に異なる。
  全葉の二重定義はしない。
- **未確定/マーカー系は raw 専用**（親文字未確定の `PendingRuby`,
  `UnresolvedRef`, ブロックマーカー, `Close{explicit}`, `LineJisage`）。
  中立AST からは型として表現不能にする（→ 3.2 の型の壁）。
- Rust らしい自然な型（enum + `Vec`）に収め、GAT 等の型トリックは入れない。

### 3.2 型の壁（ドリフト対策の中核）

「設計から外れたコードが**書けない**」ことをコンパイラに強制させる。
コメントや規約による抑止はドリフトに敗ける前提で設計する。

- 中立AST の型に Raw 概念（未解決参照・マーカー）を含めない
  → レンダラに「通常ここには来ない」死にアームが存在し得なくなる。
- バックエンドには中立AST だけを渡し、**ソース文字列を渡さない**
  → 生の行を再パースするハック（`line.contains("地付き")` 等）が書けなくなる。
- crate 分割で依存方向を固定（Rust の crate グラフは非循環なので、
  層違反はビルドエラーになる）。将来的には
  記法定義データ＋型 / core（パース・Lower） / 各バックエンド の分割を検討。

### 3.3 Quirks: 参照実装の癖の隔離

byte 互換のためだけに再現している「参照実装のバグ・実装都合」は、意味と分けて
`Quirks` フラグに隔離する（実装済み）。

- 既定オン（＝参照実装に一致）。`Quirks::none()` で規格に沿った出力。
- 各 quirk は「どのバグを再現しているか」を仕様に記録し、on/off 両方の
  適合ケースを持つ（ペアテスト方針）。
- 例（実装済み）: 外字 alt 内の入れ子 `※［＃…］` の `<img>` 展開（不正 HTML）、
  画像の空 `width="" height=""`、アクセント名 `A^` の字母欠け。
- **terprip の `<br/>` 残余**（bare `字下げ終わり` と `ここで字下げ終わり` の
  `</div>` / `</div><br/>` 差）も意味ではなく実装都合。中立AST は構造だけを持ち、
  この差は `Line.brk` に「aozora2html 互換・意味ではない」と明示ラベルした
  互換メタデータとして Lowerer が計算し、1 本のチャネルに封じ込める。

### 3.4 位置情報（任意・品質向上）

各ノードにソース位置（byte 範囲）を持たせると、精密な診断
（「N 行目のこの注記が閉じていない」）・リンタ・整形ツールの土台になる。
コーパス拡張（新規作品の検証）を直接支える。
lossless CST（rowan 型）は理論上の最上位だが、**生存性には直交**する
品質向上要素であり、優先度は仕様＋適合性より下。

## 4. ドリフト対策の機構（まとめ）

| 機構 | 防ぐもの | 状態 |
|---|---|---|
| 型の壁・crate DAG（3.2） | 層違反・Raw 概念の漏出 | 一部実装済み、段2b/2c で完成 |
| 適合性スイート＋オラクル baseline | 挙動の回帰 | 実装済み（aozora-htmlcheck） |
| 記法定義データの荷重化 | 定義と実装の乖離 | 未着手 |
| 仕様 ID カバレッジゲート（全規則に ≥1 適合ケース） | 仕様の空文化 | 未着手 |
| Quirk ペアテスト（on/off 両方） | 互換と規範の混線 | 実施中（方針化済み） |
| コメント方針（規範禁止・ID 参照のみ） | コメント腐敗 | 方針化。既存コメントは移行対象 |
| 日付つき決定記録（5 章） | 「なぜ」の喪失 | 本文書で開始 |

## 5. 決定記録（日付つき・追記のみ）

過去形の事実として記録する。腐らない。

- **2026-07** 公開 HTML をオラクルにしない。実測で公開 HTML の約 6 割が
  古い世代の生成器の出力のままであり（400 件標本で現行参照実装と byte 一致は
  41%）、参照実装の出力を全件生成してオラクルとした。
- **2026-07** 参照実装のバグは再現しつつ Quirks に隔離する。互換（既定オン）と
  規範（`none()`）を単一実装で両立し、将来フラグごと落とせる形にする。
- **2026-07** 行を第一級の構造ノードとする。行スコープコマンドの存在と
  「ソース 1 行 ≒ 論理行」から、行は構造であると判断。
- **2026-07** terprip の `<br/>` 差（bare/ここで）は意味ではなく実装都合と判断。
  作者が使い分けている可能性は無いとの判断により、互換メタデータ
  （`Line.brk`）として隔離する。
- **2026-07** 「木化より記法のデータ駆動化が先」。最深の負債は記法の定義が
  コードの副作用としてしか存在しないことであり、木化はそれを形式化しない。
- **2026-07** コードは一次アーティファクトに含める（挙動の担体として）。ただし
  意図の担体としては信頼せず、意図は型構造・仕様データ・適合スイートに載せる。
  コメントには規範を書かない（腐敗するため）。荷重原則を最上位に置く。

## 6. 移行の段階（実施状況）

byte 一致を安全網に、挙動不変を保ちながら刻む。`aozora-htmlcheck` の
`--baseline` と全件出力ハッシュ比較で各段の回帰 0 を確認する。

- **段1（完了）**: パーサと Lowerer の継ぎ目を型で導入（`RawAst`/`Ast`、
  `parse_raw` → `lower`）。挙動不変。
- **段2a（完了）**: 文書単位の RawAST を実体化（`RawLine`/`RawDoc`/
  `parse_document_raw`）。「文書単位パース → 行ごと描画」に分離。挙動不変。
- **仕様の書き起こし（次の最優先）**: 2025-26 の互換性改修で発掘された規則群
  （ヘッダ直後 1 行だけを見る注記判定、前方参照の入れ子「」文法、
  文字種 :else のルビ親文字規則、外字 `※` の出力条件、CRLF のみ改行、ほか約 30 件）
  は現在コミットメッセージとコメントにしか存在しない。**知識が新鮮なうちに**
  仕様 ID ＋実行可能実例へ移す。適合ケースの初期データは互換性改修時の
  最小再現群から作る。
- **段2b（未着手）**: Lowerer がブロックを部分木化し、レンダラを木歩きに切替。
  BlockManager 撤去。現行状態機械の忠実移植を要する大規模書き直し。
- **段2c（未着手）**: `Line.brk` を Lowerer に集約、レンダラの文字列詮索を撤去。
- **（将来）記法のデータ駆動化**: 注記一覧をデータ化し、パーサを
  それを消費する薄い機構に刷新（荷重原則を満たす形で）。
- **（将来）位置情報・プロパティベーステスト**。

これまでのリファクタ（型付き `RefSpec`、`explicit_close` の第一級化、
CSS クラスの AST 追い出し、`RawDoc` 実体化）はいずれも目標形の中盤への
前進であり無駄にならない。

## 8. 用語

| 用語 | 意味 |
|---|---|
| RawAST | パーサが記法を忠実に変換した木（前方参照未解決・ブロックは平坦マーカー・raw 専用ノードを含む） |
| Lowerer | RawAST → 中立AST への変換処理（前方参照解決・ブロック部分木化・行束ね・break 計算） |
| 中立AST | バックエンドが消費するクリーンな木（block / line / inline）。Raw 概念を型として含まない |
| Quirks | 参照実装のバグ・実装都合を byte 互換のためだけに再現する挙動を隔離するフラグ群 |
| オラクル | 参照実装 aozora2html の全件出力アーカイブ（互換性の判定基準） |
| 注記一覧 | 青空文庫が定める記法の公式ドキュメント。記法定義データの源 |
| 仕様 ID | 記法・挙動の規則ごとの安定識別子。適合ケースとコード中の参照が紐付く |
| 荷重原則 | 真実は「偽になったとき何かが壊れる場所」にだけ置く、という本設計の最上位原則 |
